ASC Default is the familiar assignment name associated with Azure Security Center, now Microsoft Defender for Cloud. The assignment connects a collection of security checks to an Azure scope. The default initiative examined here is the **Microsoft cloud security benchmark**, which Defender for Cloud uses to assess security configuration and provide recommendations. [Microsoft’s default initiative reference](https://learn.microsoft.com/en-us/azure/defender-for-cloud/policy-reference#defender-for-clouds-default-initiative-microsoft-cloud-security-benchmark)

**Snapshot: 224 policies — 99 Audit, 109 AuditIfNotExists, and 16 Disabled. None of these default effects blocks deployments or automatically changes a resource.**

[Jump to the full policy table](#all-224-policies) · [Understand the effects](#read-the-effect) · [Check your own assignment](#read-a-policy-in-your-own-environment)

A policy name describes the security requirement. Its configured **effect** tells you what Azure does when the rule finds a problem. Start with the effect when deciding whether a policy reports a finding, blocks a change, or changes a resource. [Azure Policy effects](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/effect-basics)

## Three objects to recognize

| Object | What it means | Example |
|---|---|---|
| Policy definition | One reusable rule: its conditions, parameters, and effect. | Check whether an application requires HTTPS. |
| Initiative | A collection of policy definitions grouped for a shared purpose. | Microsoft cloud security benchmark. |
| Assignment | Applies a definition or initiative to a scope with chosen parameter values and settings. | Apply the benchmark to a subscription. |

An assignment at a management group can cover its child subscriptions. Subscription assignments can cover their resource groups and resources. The individual rule still determines which resources are relevant, and exclusions or exemptions can narrow coverage. [Policy objects](https://learn.microsoft.com/en-us/azure/governance/policy/overview#azure-policy-objects) · [Assignment scope](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/scope#assignment-scopes)

## Why ASC Default can appear automatically

Defender for Cloud uses the benchmark as its default security assessment initiative. Microsoft documents its automatic assignment as part of the service’s compliance assessment. This is why an assignment can appear with Security Center as its creator even when nobody manually selected each policy in Azure Policy. [Automatic benchmark assignment](https://learn.microsoft.com/en-us/azure/defender-for-cloud/zero-trust#zero-trust-and-defender-for-cloud)

The documented Azure onboarding flow enables basic Defender for Cloud features, including recommendations, Secure Score, and benchmark assessment. This automatic flow explains how the baseline can appear. Identifying the person or automation that triggered a particular assignment requires its creation records. [Azure onboarding](https://learn.microsoft.com/en-us/azure/defender-for-cloud/connect-azure-subscription#enable-defender-for-cloud-on-your-azure-subscription)

Foundational security posture management is free. This default assignment alone does not show that a paid Defender plan is enabled. [Free and paid CSPM plans](https://learn.microsoft.com/en-us/azure/defender-for-cloud/concept-cloud-security-posture-management#cspm-plans)

**Dated service note:** Microsoft has announced that new Azure subscriptions will need to opt in to Foundational CSPM from **27 October 2026**. Existing enabled subscriptions keep their configuration. This page’s snapshot was checked on **5 September 2026**. [Microsoft’s announced change](https://learn.microsoft.com/en-us/azure/defender-for-cloud/foundational-cspm-opt-in)

## Read the effect

| Effect | What Azure does | Simple example |
|---|---|---|
| **Audit** | Reports a resource that matches the non-compliance rule. It allows the request to proceed. | Report an application that permits unencrypted HTTP. |
| **AuditIfNotExists** | Checks for a related resource or required configuration and reports the original resource when that requirement is missing. | Report a resource without the required diagnostic settings. |
| **Disabled** | Skips evaluation of that policy rule. The policy can remain listed in the initiative. | Keep a check in the collection while its effect is disabled. |

Audit can produce a warning in the Activity Log during a create or update request. A regular compliance scan updates compliance status. AuditIfNotExists runs its related-resource check after a successful resource operation. Neither effect deploys the missing configuration. [Audit](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/effect-audit) · [AuditIfNotExists](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/effect-audit-if-not-exists)

A Disabled policy has a default compliance state of Compliant. That state does not establish that a resource meets the security requirement, because the rule is disabled. [Disabled effect](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/effect-disabled)

## Defaults and enforcement answer different questions

Parameter values select how a reusable policy operates. An initiative may pass its own parameters into a policy; an assignment may supply values for those initiative parameters. If no assignment value is supplied, the initiative default is used. If the initiative does not pass a policy parameter, that policy’s own default applies. [Initiative parameters](https://learn.microsoft.com/en-us/azure/governance/policy/overview#initiative-definition)

**Enforcement mode controls whether the selected effect runs.** `Default` permits the configured effect to operate. An Audit policy therefore audits; a Deny policy can block a matching request. `DoNotEnforce` continues compliance evaluation while suppressing enforcement of the effect. The policy effect `Disabled` skips the rule itself. [Enforcement mode](https://learn.microsoft.com/en-us/azure/governance/policy/concepts/assignment-structure#enforcement-mode)

Teaching example: a rule with effect `Deny` and assignment mode `DoNotEnforce` can report a violation without blocking the request. Changing its enforcement mode to `Default` enables that Deny effect.

## Read a policy in your own environment

1. Open the assignment and check its scope and inherited coverage.
2. Record the resolved initiative and policy versions.
3. Inspect parameter values, effect overrides, and enforcement mode.
4. Check exclusions, resource selectors, and exemptions.
5. Read the rule to understand which resources it evaluates.
6. Open compliance results separately to see the actual resources affected.

This order separates the intended rule, the configured behavior, and the observed result.
